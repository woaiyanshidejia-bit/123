# YINGBA 润滑油客户邮箱工作台

**本地可运行的工程交付版；真实采集尚未连接，不能开始获取真实客户。** 开发、模拟与检查全部在云端完成，无需用户电脑开机。

中文本地网页 + Python + SQLite。范围仅为 Apollo 公司搜索 → 历史及当批去重 → 公开来源核实及邮箱补充 → 不足补搜 → Excel。没有邮件标题、正文、中文翻译、导入邮件或发送功能。

## Windows 使用

1. 将整个交付包解压到自己的普通文件夹（例如 `D:\YINGBA`），不要在 ZIP 中直接运行。
2. 首次需安装 **Python 3.12 64位**，勾选 Python Launcher / Add Python to PATH。双击 **安装.cmd**。依赖从随包 wheels 离线安装，不需要编程，也不需要购买 API。
3. 双击 **启动.cmd**，自动打开 `http://127.0.0.1:8765`。关闭启动窗口会停止程序。
4. 先在“任务设置”导入历史 Excel；再创建任务。真实模式目前会显示“未连接”并暂停。可选择“模拟验收”，目标设为15验证全流程，模拟结果始终带标记。
5. 在“导出”下载 Excel 与追溯 JSON。正式工作簿仅包含合格公司和去重邮箱，JSON 保留排除原因和原始来源。

详细操作见 [中文使用指南](docs/使用指南.md)，实际检查见 [测试报告](docs/测试报告.md)，回来后最少操作见 [本机验收清单](docs/本机验收清单.md)。

## 当前边界

- 默认目标1000家；只计已核验、主体及润滑油业务明确、具有可归属且在来源原文出现的同域商务邮箱的唯一公司。未审核、缺邮箱、排除项不计数。整批处理后判断，保留超额。
- 真实 Apollo 适配器、真实网页核实连接未验收。不会继承聊天插件。不会调用付费 Apollo，不会启动真实1000家公司采集。
- Codex 官方订阅 CLI 登录/只读诊断/显式调用桥接已编写，但实际订阅调用未验收，未接入工作队列。界面只显示 CLI 登录状态和真实联调待验收，不宣称可用。没有 API 回退。
- “模拟验收达标”和“真实验收完成”是不同状态。随包示例是虚构 `.example` 数据，不是真实客户。
- 公网核实 ≠ 邮箱实际投递验证。
- 每日北京时间全账号50分的原子预留/结算/未知结果对账机制已测试；本地账本无法观察外部应用扣费，多副本不能各自独立记账。真实付费接口接通前必须共享唯一账本并核实其它来源用量，未知必须暂停。
- Windows 10、本人浏览器登录、真实 Apollo 和真实 Codex 订阅调用还需本机验收。云端不能替本人登录。

## 开发者

Python 3.12；`python -m pip install -r requirements.lock`；`python -m unittest discover -s tests -v`；`python -m yingba.server --no-browser`。

模块：`db` 持久化，`engine` 状态机，`adapters` 模拟/未连接/订阅桥接，`budget` + `paid` 账户账本，`exchange` Excel/追溯，`server` 本地界面。浏览器测试为开发工具，不属于用户运行依赖。

未复用未知原型代码；依据描述重新实现。未更改仓库公开性。源码不含用户认证凭据。
