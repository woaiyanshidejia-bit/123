# YINGBA v1.2.0 第三轮收敛验收

本轮在云端继续修复第二轮暴露的实际运行问题。未使用用户电脑或本人浏览器，未调用真实 Apollo 账号、收费动作或真实 Codex 模型，未采集真实客户。可运行实现与模拟测试边界分开记录；最终测试数字见《测试报告》和 artifacts 原始输出。

## 第二轮结论与本轮纠正

v1.1.0 并非只有静态界面：已实现官方 Apollo HTTP 搜索、公开网页取证、运行时 `codex exec` 订阅审核、持久队列、去重、预算和 Excel，193 项测试及解包测试通过。第二轮补掉第一版的占位集成、弱主体判定、串证据风险、预算恢复及 Windows 脚本问题。

但 v1.1.0 将“没有逐动作实扣回执”统一处理为每页停止，导致人工操作过多。本轮修正：官方明确免费的端点不进入收费账本；费用和当前套餐有依据的收费动作按保守上界连续预留，实际扣费保持未知，响应不明才立即冻结。不能把收费操作误称免费，也不能把预留金额当作实扣。

## Apollo 端点、费用和权限

核对日期：2026-10-23。官方网页内容可能更新，程序运行时重新读取固定官方费用文档，并由本人订阅 Codex 评估引用；同一北京时间日、账号与固定请求的合格评估可缓存。

| 动作 | 官方端点与请求 | 当前公开费用 | 本程序处理 |
|---|---|---|---|
| 全库新公司搜索 | `POST /api/v1/mixed_companies/search`；筛选为查询参数，数组为 `[]`，page/per_page | 当前方案每页1积分、最多100结果；旧套餐可能不同 | 已实现；先确认当前账号适用费率、预算和授权；只支持已核实的现行1积分/页自动批次。其它费率/旧套餐不猜测 |
| 已保存公司读取 | `POST /api/v1/accounts/search`；JSON body，名称/列表ID/页码 | 端点明确0积分 | 已实现，连续分页，无付费回执要求；只读取账号已保存公司，耗尽不转收费 |
| 全库人员搜索 | `POST /api/v1/mixed_people/api_search` | 端点明确0积分 | 本程序未将其包装成免费全库公司搜索：响应的organization只保证有限字段，缺少本流程必须的公司域名/身份保证；人员ID不能冒充公司ID，且不返回邮箱 |
| 公司/人员补全 | organization enrichment；people enrichment等 | 公司通常1/公司；人员及waterfall依数据/供应商可能更高 | 未调用，不自动补全、不解锁私人邮箱或手机号 |
| 已有 Apollo 文件 | 本机 CSV/XLSX 导入，无网络动作 | 导入本身不调用Apollo | 已实现，保存原始文件、来源声明和逐行原文；导出文件在Apollo侧的费用仍须看对象和套餐，不能一概称免费 |

来源：[公司搜索](https://docs.apollo.io/reference/organization-search)、[已保存公司](https://docs.apollo.io/reference/search-for-accounts)、[人员搜索](https://docs.apollo.io/reference/people-api-search)、[费用表](https://docs.apollo.io/docs/api-pricing)、[权限FAQ](https://docs.apollo.io/docs/developer-faqs)。

在线 Apollo 路径使用官方 API key，而不是聊天里的插件。可为端点范围的 key 或 Master key，取决于官方权限设置。Free/Basic 名称不足以证明端点可用：官方称所有方案至少有基础API，先进功能取决于方案；部分数据库搜索还要求工作邮箱和账号资格。用户当前账号权限、旧/现行套餐、剩余额度均未知，本轮没有登录核实。健康检查只证明当次认证，不证明搜索权限。

官方文件途径可用已有公司/联系人导出作为候选来源，必须保留公司名称及官网域名。已保存联系人导出与新解锁邮箱不同，不能将其费用混淆。导入中字段不足的公司会保留排除原因，文件中的邮箱不会自动算合格证据。没有可验证的“无条件免费、全库润滑油公司及邮箱、无需API权限”的自动通路，本版不虚构该能力，也不转用网上新搜公司。

| Apollo文件候选 | `apollo_import.prepare_import/page_import`；`runtime.append_import`；`POST /api/candidates/import` | CSV编码/分隔符、XLSX、来源声明、大小限制、原件留存、同批幂等、并发追加和回滚、同任务补足 |

| 费用判定与执行分离 | `cost_policy.CostPolicy.assess`；`POST /api/cost/assess` | 固定官方来源、账户费用声明、模型与代码相符才授权；未知不归零；凭据输入拒绝；免费不进付费账本 |
| 预算与批次对账 | `PaidGateway.authorize_bounded/execute_bounded/reconcile_verified_batch`、`Budget` | 并发原子占用、unknown冻结、实际NULL、跨日、崩溃、不重复请求、对账整批回滚、上界突破撤销授权 |

运行时 Codex 是业务架构的一部分，负责公司主体/业务、邮箱归属与费用文字理解。程序提供抓取的原文和固定动作，模型只返回结构化结论与引用。代码验证公司/邮箱域名、完整原文、业务初筛、费用端点和上界；模型没有直接执行Apollo、改变预算或购买权限的入口。仅本机文件导入这类确定无Apollo调用的动作无需让模型推测费用。

官方订阅路径为本人 `codex login` 后的 `codex exec`，强制ChatGPT登录方式和内置OpenAI供应商，无API key回退。CLI实际功能和沙箱能力须匹配并通过固定样本验收；新版合同版本变化要求重新验收。因此真实集成不只是欠一个登录：仍有CLI版本/Windows沙箱、网络、权限和真实样本质量条件。

## 减少操作但保留账本真实性

1. 免费已保存公司：连接已有API权限、通过订阅验收后，程序核对官方零积分证据并连续翻页；无需确认预算或填写逐页费用。免费动作不会消除原来的未知收费账。
2. 已有Apollo文件：一次批量导入，运行时Codex核实。数量不足可向原任务追加新文件，历史和本批重复继续排除。无需Apollo API key。
3. 明确收费搜索：本人一次提供当前账号费用原文、声明当前适用方案与无账本外同时支出，确认今日全账号基线，Codex加代码核实后授予本日固定条件的授权。每页按1分上限占用，`used + held + next <= 50`才发送；完整可信响应进入`observed_pending`，`actual=NULL`，可继续同日批次。
4. 实际费用核清后，可单动作对账；若确实逐项核实同一授权批次每个动作实扣相同，可一次保存整批，不能只凭标价按1分填充。未知结果不允许批量结算；任何一项错误整批回滚。
5. 网络结果未知、结构不明、实际费用超过核实上界、跨日有未结项或全账号用量未知，都暂停且不盲重发。日期变化不会清除未知动作。暂停任务可续期授权，已存旧页仍绑定原授权重放。

同一SQLite覆盖全部本机任务；程序无法观察其它安装/应用/人员的账号支出。全账号50分保证依赖真实基线和执行期间无账本外扣费的有效声明，不能宣称跨所有设备自动监控。未确认当前套餐仍不能自动付费；没有自动购买入口。

## 审核修复与未闭合的外部条件

已修：账户ID/组织ID分开、历史Excel往返保留账户ID；初始导入批次重复追加不污染记录；同批并发幂等；总数与页数矛盾不提前完成；旧免费缓存重新校验；财务对账不能替代业务结构验收；旧任务无新授权不能发起新收费请求；续期后旧页使用原费用上界；Windows清单统一正斜杠，危险ZIP路径拒绝；下载拒绝Windows盘符和NTFS附加流路径。Apollo统一总时限覆盖DNS、TCP/TLS、响应头及响应体，DNS迟返回不会迟发请求，慢响应能中断。

Apollo全库响应若混合`accounts`与`organizations`，官方当前契约没有明确其联合分页语义。本程序保存完整脱敏响应和候选观察，标为`schema_review_required`，不丢数据、不猜合并、不重发。即使费用已核清，也不能把未验收响应算作已完成。这是数据契约的外部阻塞，不能描述为只欠登录。

官网核实采用静态HTTPS同域公开商务邮箱。JS页面、验证码、跨域邮箱、公共邮箱、主体歧义不会自动合格；页面拒绝访问和不可读会明确暂停，不绕过。公开来源核实不等于投递验证。实际1000家达标取决于可用候选及有效证据，本次没有真实达标名单。

云端通过web工具核对了官方文档；执行环境直接HTTPS获取该文档未成功，最终定位为官方文档域名DNS解析失败，运行时文档读取器由本地HTTP服务测试。Windows网络能否直接读官方文档必须实机验收，失败保持费用未知，不悄悄使用过时标价。本人订阅实际调用、Apollo实际权限/收费和Windows原生CLI沙箱均未实测。

最小本机操作见《本机验收清单》：解压安装启动；本人官方订阅登录和固定样本验收；选择已有Apollo文件或已有API权限；仅收费路线额外确认费率与今日预算；先少量真实样本再决定长期运行。用户无需补写代码。
