# 架构与接入（v1.2.0）

## 控制链与三种真实来源

`server.serve` → `Engine(source_factory=Runtime.source_for_task)`。普通 Python 代码控制状态、分页、费用、授权、预算和导出；Codex 只接收已经取得的证据，返回结构化辅助判断。没有让模型直接调用 Apollo 或决定继续付费的入口。

| 来源 | 候选入口 | 核实链 | 费用处理 |
| --- | --- | --- | --- |
| `apollo_accounts` | `AccountsSource` → 官方 Accounts Search，读取已保存公司 | `PublicVerifier` → `review_company` → 代码交叉校验 | 当日官方费用证据 + `review_cost` + 固定免费端点策略；有效结果按账号/固定请求缓存。不走收费预算或对账 |
| `apollo_import` | `prepare_import` / `page_import`，已有 Apollo CSV/XLSX | 同一官网与订阅核实链 | 本地导入不调用 Apollo、不需要 API key。不能把 Apollo 导出操作本身声明为免费 |
| `apollo_organizations` | `RealSource` → 官方 Organization Search | 同一官网与订阅核实链 | 当日固定收费授权、原子上界预留、确定性响应校验；同日有效批次连续分页，实扣后核 |

模拟任务使用独立 `MockSource`，所有身份与文件有模拟标识。公司资格不能由模拟、导入邮箱或模型裸布尔值直接产生。

真实任务的来源、筛选、每页数量、账号备注和来源批次/费用策略 ID 持久化在 `task_settings`。API key 仅保存在当前 Runtime 进程内存，不写入设置或数据库。搜索条件保持固定；续期只更换有效费用授权，不改原查询。

## 费用语义评估与确定性策略

`CostPolicy.assess` 按已实现来源选择固定官方文档。`OfficialDocumentReader` 取得原文后，代码先核对明确费用条款，再调用 `CodexSubscription.review_cost`，最后再核对返回端点、计费单位、金额、套餐和逐字引用。网页或用户账户文字始终是数据，不能修改流程或预算。

免费已保存公司要求固定 Accounts Search 端点明确免积分；未知不能当作 0。有效评估以北京时间日期、来源、账号和固定请求指纹保存到 `cost_assessments`，同日相同条件可复用，跨日重评。免费响应另入 `free_pages`，页码、请求哈希和内容哈希共同约束恢复。不会自动转全库搜索、保存公司或收费补全。

收费自动批次当前只支持代码已核对的现行非旧版套餐、Organization Search 每页最高 1 积分且无附加费用的组合。它同时需要官方端点/价格说明、本人提供的账户套餐页面原文与来源声明、Codex 辅助评估、代码策略、已知当日全账号基线和明确授权。用户手填估算或模型判为“paid/free”都不能直接建立收费策略。账户来源声明不是在线账单认证。

`paid_policies` 固定账号、北京时间日期、请求模板、上界和授权证据哈希；只有页码可变化。`Runtime.bind_cost_policy` 仅对停止且无在途租约的全库任务续期，沿原筛选和页大小重新校验。缺少新策略的旧任务只能读取已结算旧缓存，不会发送新收费请求。被撤销的授权不会由缓存评估自动恢复。

## 原子预算、已验证待结响应与对账

`Budget` 使用同一 SQLite 事务串行化全部任务的预留。北京时间每日上限 50 分：已核实用量 + 所有未结上界 + 新动作上界不得超限。账本只能可靠覆盖当前数据库，不能观察其它软件、安装或人员的扣费，因此明确要求执行期间没有账本外支出。

收费发送顺序为：核对有效策略 → 预留上界并绑定请求指纹 → 发送前提交 `unknown` → 最多一次传输 → 保存原响应 → 用普通代码检查内容、分页、请求归属和哈希。完整响应通过后，`PaidGateway.execute_bounded` 将状态变为 `observed_pending`，记录已验证时刻，并返回候选用于后续核实。

`observed_pending` 的 `actual` 始终为 NULL，完整上界继续占用预算。它允许同日有效批次继续分页，不要求每页停下来人工填写实扣。收到公司列表、HTTP 请求 ID、标价或剩余额度都不构成实际扣费回执。任何传输/结构结果未知保持 `unknown` 并冻结新的收费；跨日 `observed_pending` 也冻结新收费，需核清实际归属日。

`reconcile_captured` 用本人核实的动作实扣、归属日和依据结算，并发布可恢复缓存；预留不是默认实扣。`reconcile_verified_batch` 只接收明确选择的同一策略、同一发生日、已验证待结算动作，且本人已逐项核实实扣相同；一次事务全部成功或全部不改。混入 unknown、不同策略、篡改响应、重复或已结算动作会拒绝。批次核对依据仍为各动作建立可追溯记录，不能用总额平均推定各笔费用。

尚有未结动作时不能覆盖基线或建立新收费策略。超过已核实上界的实扣会撤销相关费用假设并使基线失效；记录真实实扣不意味着提高 50 分运行限额。缺失响应对账需要无在途请求，核账也不会恢复不存在的响应或重发原动作。

## 持久化、分页与恢复

SQLite WAL、FULL 同步、`BEGIN IMMEDIATE`。分页推进与整页入库一起提交；公司审核阶段、证据和邮箱一起提交。任务 owner/600 秒租约避免重复认领，文件锁限制同一数据目录单实例。暂停提交前再次核对 owner、状态与租约，旧 worker 不能覆盖新 owner。

已提交候选、原始响应、费用评估、网页缓存和导入文件跨重启保留；恢复使用原请求/响应哈希，禁止同一付费动作绑定另一请求。明确没有付费副作用的 `TransientError` 才允许最多 3 次退避。未知收费、权限、登录和配额错误进入持久暂停。

Apollo 在线请求各限定为已核对的 1–500 页；文件导入按保存文件分页，Engine 另有 1000 页安全上限。当前页候选处理完才判断合格目标，超额保留；来源耗尽、连续 3 页无新增、空页却未声明耗尽等都明确停止/暂停。自动补充指当前固定条件继续分页，不擅自扩大收费查询。

v1.2.0 迁移保留旧任务和历史，并增加费用授权、待结响应、导入文件等持久记录。未知旧动作没有请求指纹时，不伪造绑定；新版数据库拒绝被旧程序降级写入。升级先关闭程序并备份完整 `data`。

## 公司网页与运行时订阅核实

`PublicFetcher` 仅取候选同域 HTTPS，检查 DNS 公网地址、固定 IP、验证 TLS 和跳转；不带 Cookie/认证，不执行 JavaScript。单页时间和大小、页数均有限，403/429 保持暂停。`PublicVerifier` 对主体、润滑油业务及商务邮箱做保守初筛，逐页证据先保存至 `verification_cache`。

真实来源随后必须调用 `CodexSubscription.review_company`。官方 `codex exec` 强制 ChatGPT 订阅，忽略用户配置/规则、使用临时目录和只读沙箱、关闭已核对的主要工具能力。只读 `preflight` 与本人固定样本 `validate_local` 分开；后者产生绑定 CLI/合同版本、24 小时有效的验收记录。公司和费用审核共用受限进程、JSON Schema、JSONL/结果文件一致性及引用校验，异常使旧验收失效。没有任意 prompt 通道、模型 API 回退、认证复制或购买入口。

Runtime 取代码主体/业务判定与订阅结果的交集，邮箱还须属于同一证据页的商务邮箱集合；Engine 再验同域 URL、完整邮箱 token 和公司外键。规范化域名、Apollo ID、名称与邮箱在真实任务/历史之间去重，模拟命名空间独立。`raw_records` 保留重复行及原因，弱名称冲突不向旧公司传播新域名。

正式计数与 Excel 共用合格查询，缺邮箱、未审核、排除记录不进入正式总表。公开来源证明不能当作实际投递验证；跨域关联、公共邮箱、验证码、动态页面或主体不明的情形不自动合格。

## 文件导入、本机安全与验收边界

候选导入支持 CSV/XLSX，限制文件大小、行列数和编码，保存原件、内容哈希、映射、用户来源声明与逐行原文；它不同于历史排除名单。候选导入不采纳表中邮箱为核实依据。仅原文件分页已完成且任务停止时可追加批次，不切换收费来源。

HTTP 仅监听 `127.0.0.1`，检查 Host、Origin 和启动随机 CSRF 令牌；无外部前端依赖。网页数据按文本渲染，Excel 外部文本防公式注入、逐格回读后原子发布。凭据不写日志、数据库或交付包。包排除 `data`、CLI 认证、验收 receipt、`.git` 和临时文件。

本轮接口合同用本地服务/假 CLI/模拟证据验证，未调用真实模型或执行真实 Apollo 收费操作。当前云环境没有贯通运行时官方费用文档的直接联网读取；Windows 启动、官方原生沙箱、本人登录、真实接口权限/费率及实际取证质量仍待本机验收。官方没有已核实的全工具封闭保证，本机固定样本通过也不等于该保证。

实际测试数字及第三轮审核结论以 [第三轮报告](第三轮验收报告.md) 为准；[第二轮报告](第二轮验收报告.md) 作为历史证据保留。官方接口细节另见 [Apollo 核对](Apollo官方接口核对.md) 和 [Codex 核对](Codex订阅接口核对.md)。
